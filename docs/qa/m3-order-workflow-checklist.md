# M3 Order Workflow Checklist

本清单用于 M3 购物车、结算、订单创建、模拟支付和订单状态机验收。M3 的目标不是接入真实支付，而是验证交易链路在权限、库存、幂等、超时和多端状态同步上的业务正确性。

## 1. 验收范围

- 购物车：添加、修改、删除、选中、失效商品提示。
- 结算：价格重算、库存重算、地址校验、阻塞项提示。
- 订单创建：幂等创建、快照落库、库存锁定、购物车清理。
- 订单状态机：待支付、已支付待发货、已关闭，以及 M4 预留状态不可误用。
- 库存：锁定、释放、扣减、并发下单不超卖。
- 模拟支付：支付单创建、成功/失败回调、重复回调、乱序回调。
- 超时任务：支付超时关闭订单、释放库存、重复执行安全。
- 权限联动：用户、商家、管理员的数据范围、字段脱敏和审计。
- 多端状态：用户 Web、Android、商家后台、管理员后台状态一致。

## 2. 测试数据准备

- 至少 2 个普通用户：`user_a`、`user_b`。
- 至少 2 个商家：`merchant_a`、`merchant_b`。
- 每个商家至少 2 个已上架 SKU，覆盖库存充足、库存紧张、库存为 0。
- 至少 1 个下架 SKU、1 个价格会变化的 SKU、1 个不可配送地址场景。
- 管理员账号覆盖平台客服、风控审核、财务管理员、技术管理员、只读审计。
- 初始化库存需要能观察 `on_hand`、`reserved`、已扣减或库存流水变化。
- 支付超时时间在测试环境应可配置为较短窗口，例如 1 到 5 分钟。

## 3. 购物车验收

- 用户可将已上架且有可售库存的 SKU 加入本人购物车。
- 重复添加同一 SKU 时数量合并，不能绕过单次购买上限。
- 修改购物车数量为 0 或负数返回校验错误。
- 修改数量超过可售库存时返回业务错误，并提示最大可买数量。
- 用户可删除本人购物车项，删除后结算预览不再包含该项。
- 用户可切换购物车项选中状态，结算只包含选中项。
- SKU 下架后购物车保留商品行但标记失效，不能结算。
- SKU 价格变化后购物车能提示变化，结算使用实时价。
- 未登录用户进入结算时要求登录，登录后购物车合并策略不丢失本地意图。
- `user_a` 不能读取、修改、删除 `user_b` 的购物车项。
- 商家账号和管理员账号不能调用普通用户购物车写接口。

## 4. 结算验收

- 结算预览每次都重新读取 SKU、价格、库存、商家和地址状态。
- 库存充足、地址可配送、价格无变化时返回 `checkout_ready`。
- 地址缺失或信息不完整时返回 `needs_user_action`，不创建订单。
- 商品下架、库存不足、不可配送时返回 `blocked`，逐项展示阻塞原因。
- 价格变化时要求用户确认或重新结算，不能静默按旧价下单。
- 结算预览默认不锁库存；只打开结算页不应改变库存锁定数量。
- 多商家商品结算时能展示按商家拆分的商品、运费和金额摘要。
- 结算金额使用整数分或定点类型，不能出现浮点精度误差。
- 结算接口只允许当前用户处理本人购物车选中项。

## 5. 订单创建验收

- 成功创建订单后订单状态为 `pending_payment`。
- 订单保存商品快照、价格快照、收货地址快照和商家归属。
- 创建订单在同一事务中锁定库存；订单失败不能残留库存锁定。
- 成功下单后购物车中对应已选商品被清理或取消选中。
- 下单返回订单号、应付金额、支付截止时间和支付入口。
- 同一用户使用相同 `idempotency_key` 重试同一请求时返回同一订单。
- 相同 `idempotency_key` 携带不同请求摘要时返回冲突错误。
- 用户连续点击提交订单不会生成重复订单，也不会重复锁库存。
- 下单时库存不足返回 `409`，订单和库存锁定都不创建。
- 订单创建事件写入 `order_status_event`。
- 库存锁定事件和订单号、SKU、数量、幂等键可追踪。

## 6. 订单状态机验收

- `null -> pending_payment` 只能由订单创建触发。
- `pending_payment -> paid_pending_shipment` 只能由成功支付回调或支付查询补偿触发。
- `pending_payment -> closed` 可由用户取消、支付超时任务、风控关闭触发。
- `closed` 为终态，不能重新支付、重新打开或进入待发货。
- `paid_pending_shipment` 不能通过普通用户取消接口关闭。
- 支付金额不一致时不能进入 `paid_pending_shipment`。
- 每次状态迁移都记录前后状态、触发人、原因和时间。
- 非法迁移返回明确业务错误，不应静默成功。
- M3 未实现发货时，不应让普通接口把订单推进到 `shipped_awaiting_receipt` 或 `completed`。

## 7. 库存验收

- 创建订单成功后，相关 SKU 的锁定数量增加。
- 用户取消待支付订单后，锁定库存释放，可售数量恢复。
- 支付超时关闭后，锁定库存释放，可售数量恢复。
- 支付成功后，锁定库存转扣减或标记已消费，不再可释放。
- 重复支付成功回调不会重复扣减库存。
- 重复取消待支付订单不会重复释放库存。
- 取消和支付成功并发时，最终只能产生一个合法状态和一次库存动作。
- 超时任务和支付成功并发时，支付已成功落库的订单不得被关闭。
- 同一 SKU 多用户并发下单时，成功锁定总数不能超过可售库存。
- 库存扣减或释放失败时，订单状态不能提前提交为成功结果，或必须进入可观测补偿状态。

## 8. 模拟支付验收

- 只有订单本人可以为 `pending_payment` 订单发起模拟支付。
- 支付单金额必须等于订单应付金额。
- 同一订单重复发起支付时，复用有效支付单或按明确策略创建新尝试。
- 支付成功回调将支付单置为 `succeeded`，订单置为 `paid_pending_shipment`。
- 支付失败回调将支付单置为 `failed`，订单是否保持待支付或关闭需符合配置。
- 重复成功回调返回已处理结果，不重复改订单、不重复扣库存、不重复通知。
- 重复失败回调返回已处理结果，不重复通知。
- 成功后再收到失败回调时，订单保持已支付，并记录乱序事件。
- 失败后再收到成功回调时，若订单仍待支付且金额匹配，可以成功；若订单已关闭，进入异常支付记录。
- 金额不一致回调被拒绝，写支付异常和审计日志。
- 订单不存在的回调被记录为无主回调，并进入财务或技术待办。
- 回调处理必须依赖稳定幂等标识，例如模拟渠道流水号或回调事件 ID。

## 9. 支付超时关闭验收

- 订单创建时写入 `payment_deadline`。
- 支付截止前，超时任务不会关闭订单。
- 支付截止后，未支付订单被系统任务关闭，关闭原因为 `payment_timeout`。
- 超时关闭同时释放库存锁定。
- 超时关闭同时将有效支付单置为 `expired`。
- 超时任务重复执行不会重复释放库存或重复写核心状态事件。
- 已支付订单即使超过原支付截止时间，也不能被超时任务关闭。
- 支付成功回调与超时任务竞争时，最终状态必须由事务内当前状态决定。
- 用户端订单详情能展示超时关闭原因和重新购买入口。

## 10. 权限与数据范围验收

- 普通用户只能查看本人订单列表和订单详情。
- 普通用户取消他人订单返回 `403` 或按防枚举策略返回 `404`。
- 普通用户不能查看商家订单队列或管理员订单列表。
- 商家只能查看本店相关订单，不能跨商家查询。
- 商家订单列表页默认只展示已支付待履约或与本店相关的订单，不把全平台待支付订单作为待办。
- 商家列表页敏感字段脱敏，详情页按履约权限展示必要收货信息。
- 商家财务可查看本店支付摘要，但不能修改订单状态。
- 平台客服可查看订单时间线，但敏感字段访问要写审计。
- 风控审核可以关闭未支付风险订单，并必须填写原因。
- 风控审核不能关闭已支付订单，除非后续补偿流程明确授权。
- 财务管理员可查看支付单和异常支付记录，不能修改商品或发货状态。
- 技术管理员可查看任务和回调处理结果，不能直接修改订单资金状态。
- 只读审计账号不能触发任何写接口。
- 权限拒绝写入审计日志，包含操作人、接口、缺失权限、IP 和 User-Agent。

## 11. 多端状态验收

- 用户 Web 创建订单后，订单列表和详情展示 `pending_payment` 和倒计时。
- Android 创建订单后，订单状态、倒计时和支付入口与 Web 一致。
- 用户在 Web 支付成功后，Android 订单详情刷新为 `paid_pending_shipment`。
- 支付页断网或刷新后，用户可通过订单详情主动刷新支付状态。
- 支付超时关闭后，用户 Web 和 Android 都展示关闭原因。
- 支付成功后，商家后台出现对应待履约订单。
- 待支付订单不应进入商家待发货工作台待办。
- 风控关闭待支付订单后，用户端看到用户可理解文案，管理员端看到完整原因。
- 重复支付回调不应重复触发用户消息或商家待办。

## 12. 审计与事件验收

- 订单创建写订单状态事件。
- 用户取消写订单状态事件和库存释放事件。
- 支付成功写订单状态事件、支付事件和库存扣减事件。
- 支付失败写支付事件，必要时写订单状态事件。
- 支付超时关闭写订单状态事件、库存释放事件和系统任务日志。
- 风控关闭写审计日志、订单状态事件和库存释放事件。
- 支付金额不一致写支付异常和审计日志。
- 重复回调记录幂等命中，不重复写核心状态迁移。
- 管理员或商家访问敏感字段写审计日志。
- 审计日志包含操作人、角色、对象、前后状态、原因、请求 ID、IP、User-Agent 和时间。

## 13. API 与契约验收

- OpenAPI 包含购物车、结算、订单、支付、商家订单、管理员订单相关接口。
- OpenAPI 明确成功响应、业务错误、权限错误和幂等冲突错误。
- 所有创建或状态迁移接口约定 `idempotency_key` 或等价幂等标识。
- 订单、支付、库存错误码在 Web 和 Android 中可映射为用户提示。
- 订单状态枚举在后端、Web、Android、文档中保持一致。
- 支付回调接口不暴露给普通用户伪造成功结果；若使用内部签名，测试覆盖签名失败。
- API 变更需要同步类型生成和调用方。

## 14. 并发与异常回归

- 同一用户同一订单创建请求网络超时后重试，返回同一订单。
- 同一用户两个浏览器标签同时提交同一购物车，不会重复锁定同一批库存。
- 多用户抢购同一低库存 SKU，成功订单数不超过库存。
- 支付成功回调和用户取消请求同时到达，只能保留一个合法最终状态。
- 支付成功回调和支付超时任务同时到达，只能保留一个合法最终状态。
- 支付渠道重复发送 10 次成功回调，订单和库存只变化一次。
- 支付渠道先失败后成功、先成功后失败均符合模拟支付规则。
- 订单关闭后收到成功支付回调，进入异常支付待办，不重新打开订单。
- 数据库事务中途失败时，不产生半订单或半库存锁定。
- 后台任务重跑不会重复关闭或重复释放。

## 15. Web 验收

- 用户端商品详情可加入购物车，并处理库存不足、商品下架、登录过期。
- 购物车页包含选中、改数量、删除、失效商品、价格变化和加载/错误状态。
- 结算页展示地址、商品、金额、运费、阻塞项和重新计算状态。
- 下单页重复点击提交按钮不会产生重复订单。
- 支付模拟页支持成功、失败、超时或返回订单详情。
- 订单列表展示待支付、待发货、已关闭状态和关闭原因。
- 订单详情展示时间线、支付截止时间、取消入口和状态刷新入口。
- 商家后台订单列表展示本店已支付待履约订单，并有空状态和错误状态。
- 管理员后台订单查询按角色显示客服、风控、财务、审计视图。
- Web lint、typecheck、build 通过。

## 16. Android 验收

- Android 用户端能浏览商品、加入购物车、结算、创建订单和模拟支付。
- 登录态过期时保留当前购物或结算上下文。
- 弱网或支付页回退后，订单详情可刷新状态。
- 购物车、结算、订单详情覆盖加载、错误、空状态和重试入口。
- 支付成功后回到订单详情，状态为已支付待发货。
- 支付超时后订单详情展示关闭原因。
- Android 至少完成相关模块构建；若未构建，PR 需说明原因和风险。

## 17. 后端测试建议

- 状态机单元测试覆盖全部合法迁移和非法迁移。
- 库存服务单元测试覆盖锁定、释放、扣减、重复操作。
- 支付服务单元测试覆盖成功、失败、重复、乱序、金额不一致。
- 订单创建集成测试覆盖事务回滚和幂等。
- PostgreSQL 并发测试覆盖低库存抢购。
- 超时任务测试覆盖关闭、跳过已支付、重复执行。
- 权限测试覆盖用户、商家、管理员、只读审计。
- Alembic migration 可升级；高风险 migration 需要 downgrade 或回滚说明。

## 18. Release 回归清单

- 从空购物车到成功支付的用户主链路通过。
- 购物车中商品下架、价格变化、库存不足均能阻止或提示。
- 创建订单后库存锁定正确，取消和超时释放正确，支付成功扣减正确。
- 重复提交订单、重复支付回调、重复超时任务均幂等。
- 用户、商家、管理员三端订单状态一致。
- 商家不能跨店铺看订单，用户不能看他人订单，只读审计不能写。
- 风控关闭待支付订单有原因、有审计、有用户提示。
- 支付异常记录可被财务或技术管理员查询。
- OpenAPI、类型生成、Web、Android 调用方同步。
- 后端测试、Web 构建、Android 构建或说明、核心 E2E 或手工回归记录齐全。

## 19. 当前策略

- M3 支付为模拟支付，不接真实渠道，但回调、幂等和异常记录按真实渠道形状设计。
- M3 结算预览默认不锁库存，订单创建才锁定库存。
- M3 重点状态为 `pending_payment`、`paid_pending_shipment`、`closed`；发货、收货、售后和退款在 M4 深化。
- 后台页面以订单查询、风控关闭、支付异常查看和商家待履约列表为主，不做完整售后工作台。
