# M4 After-Sales, Admin, and Merchant Checklist

本清单用于 M4 售后、商家后台、管理员后台验收。M4 的目标是验证售后申请、商家处理、退货物流、模拟退款、客服介入、超时任务、权限联动和审计闭环，而不是只验证“申请、同意、退款成功”的简单路径。

## 1. 验收范围

- 售后申请：仅退款、退货退款、部分数量、金额校验、凭证上传。
- 商家审核：同意、拒绝、要求补证、处理超时。
- 用户动作：补充凭证、申请客服介入、撤销、填写退货物流。
- 退货物流：物流单录入、修改、异常、商家收货确认。
- 模拟退款：退款单创建、成功、失败、重复回调、自动重试、人工处理。
- 客服工单：争议介入、证据链、裁定、补证、结案。
- 超时任务：商家超时自动同意或升级、用户超时关闭、商家收货超时自动确认。
- 权限联动：用户、商家、平台客服、客服主管、风控、财务、技术、只读审计。
- 多端状态：用户 Web、Android、商家后台、管理员后台状态一致。
- 审计与事件：状态事件、敏感字段访问、权限拒绝、财务和客服操作审计。

## 2. 测试数据准备

- 至少 2 个普通用户：`user_a`、`user_b`。
- 至少 2 个商家：`merchant_a`、`merchant_b`，每个商家至少 1 个店主、1 个订单客服、1 个仓储发货、1 个商家财务。
- 管理员账号覆盖平台客服、客服主管、风控审核、财务管理员、技术管理员、只读审计。
- 准备订单状态：`paid_pending_shipment`、`shipped_awaiting_receipt`、`completed`、`closed`。
- 准备多商品订单、跨商家拆分订单、可部分退款订单、已部分退款订单。
- 准备未发货仅退款、已发货退货退款、超大金额退款、频繁退款风控用户。
- 准备可重试退款失败码、不可重试失败码、金额不一致回调、重复回调数据。
- 售后和退款超时窗口在测试环境应可配置为分钟级。
- 证据附件应覆盖图片、文字说明、物流凭证、商家拒绝凭证。

## 3. 售后申请验收

- 用户可对本人 `paid_pending_shipment` 订单发起仅退款。
- 用户可对本人 `shipped_awaiting_receipt` 或 `completed` 订单发起退货退款。
- 用户不能对他人订单发起售后，返回 `403` 或按防枚举策略返回 `404`。
- 已关闭、未支付或超出售后时效的订单不能发起售后。
- 售后数量不能超过订单行可售后数量。
- 售后金额不能超过订单行可退金额、运费和优惠分摊规则允许值。
- 已存在进行中售后时，不能重复占用同一订单行可售后数量。
- 用户必须填写售后原因；高金额或退货退款必须支持上传凭证。
- 创建售后成功后状态为 `merchant_review`，并写售后创建事件。
- 售后创建后用户 Web 和 Android 展示当前进度、下一步动作和商家处理截止时间。
- 售后创建后商家后台出现本店售后待处理待办。
- 跨商家订单只把相关订单行售后推送给对应商家。

## 4. 商家审核验收

- 商家订单客服只能查看和处理本店售后。
- 商家店主可查看本店售后队列和员工处理记录。
- 商家财务只能查看退款摘要，不能审核、拒绝或确认收货。
- 商家同意未发货仅退款后，售后进入 `refunding` 并创建退款单。
- 商家同意退货退款后，售后进入 `waiting_buyer_return`。
- 商家拒绝售后必须选择原因并填写说明。
- 商家拒绝时必须上传或引用规则依据、物流凭证、商品凭证等证据。
- 拒绝后用户端展示拒绝原因、补充凭证入口和客服介入入口。
- 商家要求用户补证时，用户端展示补证要求和截止时间。
- 用户补证后售后重新进入商家审核队列，并记录补证事件。
- 商家重复点击同意或拒绝不会重复迁移状态、重复通知或重复创建退款单。
- 已进入客服介入后，商家同意和拒绝入口应被冻结或按工单要求限制。
- 商家不能处理 `merchant_b` 的售后单，也不能通过猜 ID 查看详情。

## 5. 用户补证、撤销与客服介入验收

- 商家拒绝后，用户可补充凭证并重新提交。
- 用户补充凭证保留历史证据，不覆盖原始申请证据。
- 用户可在未进入退款前撤销售后，撤销后状态为 `closed`。
- 用户撤销后再次申请需遵守售后时效、可退数量和历史规则。
- 用户可在商家拒绝后申请客服介入。
- 用户可在商家超时、物流争议、商家拒收等场景申请客服介入。
- 申请客服介入后生成工单并关联订单、售后、退款和证据链。
- 工单创建后用户端展示平台处理中和可能的补证动作。
- 工单创建后商家后台展示工单状态和商家待补证动作。

## 6. 退货物流验收

- 退货退款审核同意后，用户端展示退货地址、物流填写入口和退货截止时间。
- 用户可填写物流公司、物流单号、寄出时间和备注。
- 物流单号格式错误时返回校验错误，不推进状态。
- 用户填写物流后售后进入 `waiting_merchant_receipt`。
- 用户修改物流信息必须填写原因，并记录修改前后值。
- 商家可在本店待收货队列查看退货物流。
- 商家确认收货后售后进入 `refunding` 并创建退款单。
- 商家标记未收到、错寄、破损或商品异常时，必须上传凭证并进入客服介入或争议状态。
- 商家确认收货接口幂等，重复提交不重复创建退款单。
- 用户、商家、客服均能在时间线看到物流填写、修改、商家确认或异常事件。

## 7. 模拟退款验收

- 退款单只能由售后状态机创建，普通用户和商家不能直接创建。
- 退款金额等于审核或裁定金额，不能超过订单可退金额。
- 部分退款成功后，订单行已退金额和可售后数量正确更新。
- 未发货全额仅退款成功后，订单联动关闭或展示全额退款完成，关闭原因明确。
- 退货退款成功后，售后状态为 `refunded`。
- 模拟退款成功回调将退款单置为 `succeeded`，售后置为 `refunded`。
- 重复成功回调返回已处理，不重复退款、不重复通知、不重复写核心状态迁移。
- 首次失败回调将退款单置为 `failed`，售后置为 `refund_failed`。
- 可重试失败码触发自动重试，重试次数、下次重试时间和失败码可查询。
- 不可重试失败码进入 `refund_failed`。
- 超过重试上限后进入 `refund_failed`，并生成财务待办。
- 财务管理员可重新发起退款或人工标记完成，必须二次确认并填写原因。
- 财务管理员人工完成后写财务审计，用户和商家看到退款完成。
- 金额不一致回调不能置成功，必须进入异常或人工复核。
- 退款单不存在的回调记录为无主回调，财务和技术管理员可查询。
- 成功后再收到失败回调时保持成功，并记录乱序事件。

## 8. 客服工单验收

- 用户申请客服介入后生成工单，工单绑定订单、售后、用户、商家和证据。
- 商家审核超时自动升级时生成工单，工单来源为系统任务。
- 商家拒收、物流异常或双方证据冲突时可生成工单。
- 平台客服可查看完整时间线和必要证据链。
- 平台客服访问完整手机号、地址、支付流水等敏感字段时写审计。
- 平台客服可要求用户补证，并设置补证截止时间。
- 平台客服可要求商家补证，并设置补证截止时间。
- 客服裁定同意仅退款后，售后进入 `refunding` 或财务复核。
- 客服裁定退货退款后，售后进入 `waiting_buyer_return`。
- 客服裁定驳回后，售后进入 `closed`，用户端展示可理解原因。
- 超大金额、风控命中或渠道异常退款不能由客服直接完成资金状态，必须交财务复核。
- 客服主管可处理升级工单或复核批量裁定。
- 只读审计可以查看工单和日志，不能评论、裁定或修改状态。
- 工单结案必须包含结论、依据、引用证据、用户可见文案和商家可见文案。

## 9. 超时任务验收

- 商家审核截止时间写入售后单，并在商家后台列表展示剩余时间。
- 低金额或规则明确的商家审核超时场景自动同意。
- 自动同意仅退款后进入 `refunding`，并创建退款单。
- 自动同意退货退款后进入 `waiting_buyer_return`，并通知用户退货。
- 高金额、风控命中或证据复杂的商家审核超时场景自动升级客服。
- 自动升级客服后创建工单，商家审核入口受限。
- 用户退货截止时间到期且未填写物流时，售后自动进入 `closed`。
- 用户超时关闭后用户端展示关闭原因和再次申请规则。
- 商家收货确认截止时间到期且无拒收或异常凭证时，系统自动确认收货。
- 商家收货超时自动确认后售后进入 `refunding`。
- 证据补充超时后，系统按规则关闭、维持拒绝或交由客服裁定。
- 退款失败重试任务重复执行不会重复发起多笔退款语义。
- 所有超时任务重复执行时应跳过已处理对象，并记录跳过原因。
- 超时任务写系统任务日志、状态事件、审计日志和通知。

## 10. 权限与数据范围验收

- `user_a` 只能查看和操作自己的售后，不能查看 `user_b` 的售后。
- 普通用户不能进入商家售后队列或管理员工单列表。
- 商家只能查看当前 `merchant_ids` 范围内的售后，不能跨店铺。
- 商家列表页手机号、地址、支付流水默认脱敏。
- 商家详情页只对有售后处理或履约权限的员工展示必要敏感字段。
- 仓储发货可登记收货异常凭证，不能审核售后诉求或裁定退款。
- 商家财务可查看本店退款记录和结算影响，不能改售后状态。
- 平台客服只能在订单查询、售后或工单上下文访问必要敏感字段。
- 风控审核可查看风险售后并冻结高风险退款待复核，不能普通客服裁定。
- 财务管理员可查看退款失败码、重试记录和人工处理入口。
- 技术管理员可查看任务、日志、幂等记录和回调处理结果，不能直接裁定售后。
- 只读审计不能触发任何写接口。
- 所有权限拒绝写审计日志，包含操作人、接口、缺失权限、IP 和 User-Agent。

## 11. 多端状态验收

- 用户 Web 提交售后后，Android 订单详情能刷新出相同售后状态。
- Android 补充凭证后，用户 Web 和商家后台同步展示新证据。
- 商家同意仅退款后，用户 Web 和 Android 展示退款处理中。
- 商家同意退货退款后，用户 Web 和 Android 展示填写物流入口。
- 用户填写退货物流后，商家后台出现待确认收货。
- 商家确认收货后，用户端展示退款处理中，管理员财务可见退款单。
- 退款成功后，用户 Web、Android、商家后台和管理员后台状态一致。
- 商家拒绝后，用户端展示补证和客服介入入口，管理员可查看争议候选。
- 客服介入后，用户端和商家后台都展示平台处理中，但内部备注不外显。
- 退款失败时，用户端展示处理中或异常处理中，不暴露内部失败码。
- 管理员财务和技术视图可看到退款失败码、重试次数和幂等记录。
- 重复回调、重复超时任务、重复点击操作不应重复触发用户消息或商家待办。

## 12. 审计与事件验收

- 售后创建写售后状态事件。
- 商家同意、拒绝、要求补证写售后事件和审计日志。
- 商家拒绝和拒收必须记录原因、凭证、操作人和时间。
- 用户补充凭证、填写物流、修改物流、申请介入写事件。
- 客服工单创建、评论、补证要求、裁定、结案写工单事件和审计日志。
- 财务退款重试、人工完成、人工驳回写退款事件和审计日志。
- 退款成功、失败、重复、乱序、金额不一致回调写退款事件。
- 超时自动同意、自动升级、自动关闭、自动确认收货写系统事件。
- 商家、客服、财务、技术访问敏感字段写敏感访问审计。
- 审计日志包含操作人、角色、对象、前后状态、原因、证据、请求 ID、IP、User-Agent 和时间。
- 审计日志中的内部备注、风控规则和敏感凭证不应外显给用户或商家。

## 13. API 与契约验收

- OpenAPI 包含用户售后、商家售后、管理员工单、退款和超时任务相关接口。
- OpenAPI 明确售后状态、退款状态、工单状态枚举。
- 创建、审核、补证、物流、客服裁定、退款重试等写接口约定幂等键。
- API 明确业务错误、权限错误、状态冲突、幂等冲突和附件校验错误。
- 后端、Web、Android 的售后状态枚举和文案映射保持一致。
- 退款失败码有前端可展示文案和管理员内部说明的区别。
- 附件上传限制文件类型、大小、数量，并有恶意文件处理策略。
- API 变更同步类型生成和调用方。

## 14. 商家后台验收

- 售后列表支持按状态、超时风险、金额、售后原因、物流状态筛选。
- 售后列表显示剩余处理时间、风险等级、申请金额、订单号和用户脱敏信息。
- 售后详情展示用户诉求、商品快照、订单时间线、证据链和商家操作区。
- 同意售后操作有金额确认，超出规则金额需阻止或提示升级。
- 拒绝售后必须二次确认、填写原因并上传凭证。
- 待买家退货、待商家收货、退款跟踪有独立队列或清晰筛选。
- 商家收货确认支持异常凭证上传和申请客服介入。
- 商家财务视图展示退款记录、结算影响和只读状态。
- 加载、空状态、错误状态、权限不足状态完整。
- 表格和详情页在窄屏下不出现文字遮挡或关键按钮不可见。

## 15. 管理员后台验收

- 后台首页按角色展示待办：客服看工单，财务看退款异常，风控看风险售后，技术看任务和回调。
- 客服工单列表支持按队列、优先级、状态、商家、超时风险筛选。
- 工单详情展示完整时间线、双方证据、订单信息、售后信息和可见性分区。
- 客服裁定必须填写原因，并选择用户可见文案和商家可见文案。
- 客服要求补证时可设置对象、问题、截止时间和证据类型。
- 财务退款异常列表展示失败码、重试次数、金额、渠道流水和处理入口。
- 财务人工完成退款需要二次确认、原因和审计。
- 风控视图展示频繁售后、异常金额、疑似欺诈和冻结状态。
- 技术视图展示超时任务运行结果、幂等命中、回调原始摘要和错误原因。
- 只读审计视图可检索售后、退款、工单、权限拒绝和敏感字段访问日志。
- 后台敏感字段按角色脱敏，点击查看完整字段时必须有授权和审计。

## 16. 并发与异常回归

- 用户重复提交同一售后申请返回同一结果或明确幂等冲突。
- 同一订单行两个售后并发申请不会超过可售后数量或金额。
- 商家同意与用户撤销同时发生时，只保留一个合法最终状态。
- 商家拒绝与系统超时自动同意同时发生时，最终状态由事务内当前状态决定。
- 用户填写物流与用户超时关闭任务同时发生时，不能既关闭又待收货。
- 商家确认收货与商家收货超时自动确认同时发生时，只创建一笔退款单。
- 退款成功回调与退款失败回调乱序到达时，最终状态符合退款规则。
- 退款自动重试与财务人工处理同时发生时，不产生重复退款语义。
- 客服裁定与商家后续操作冲突时，商家操作被拒绝或按工单约束处理。
- 数据库事务中途失败时，不产生半售后、半退款或孤儿工单。
- 附件上传失败时，不推进售后状态。

## 17. Web 与 Android 验收

- 用户 Web 订单详情展示申请售后入口、售后进度、下一步动作和截止时间。
- 用户 Web 售后申请表覆盖原因、金额、数量、凭证、提交中、错误和成功状态。
- Android 覆盖售后申请、补充凭证、填写物流、查看进度。
- 登录态过期时保留售后申请上下文，重新登录后可继续。
- 弱网或页面回退后，售后详情可主动刷新状态。
- 用户端不显示内部失败码、风控备注、客服内部备注。
- 商家后台和管理员后台关键页面 Web lint、typecheck、build 通过。
- 关键售后链路有 Playwright E2E 或明确手工回归记录。
- Android 至少完成相关模块构建；若未构建，PR 需说明原因和风险。

## 18. Release 回归清单

- 用户从已支付未发货订单申请仅退款，商家同意，模拟退款成功。
- 用户从已发货订单申请退货退款，商家同意，用户填写物流，商家确认收货，模拟退款成功。
- 商家拒绝后用户补证，商家再次审核通过。
- 商家拒绝后用户申请客服介入，客服裁定退款。
- 商家审核超时低风险自动同意，高风险自动升级客服。
- 用户超时未退货自动关闭。
- 商家收货超时自动确认并推进退款。
- 退款失败可自动重试，超过重试上限进入财务人工处理。
- 退款金额不一致回调不能置成功，有财务和技术待办。
- 用户、商家、管理员三端状态、时间线和通知一致。
- 用户不能查看他人售后，商家不能跨店铺处理，只读审计不能写。
- 客服不能绕过财务复核直接完成大额或异常退款。
- 所有敏感操作、权限拒绝、客服裁定、财务处理和字段访问有审计。
- OpenAPI、类型生成、Web、Android 调用方同步。
- 后端状态机测试、退款测试、权限测试、超时任务测试、Web 构建、Android 构建或说明齐全。

## 19. 当前策略

- M4 退款仍为模拟退款，但按真实渠道的幂等、回调、失败码、重试和人工处理形状设计。
- M4 优先实现仅退款和退货退款；换货、维修、价保后续扩展。
- 订单主状态保留履约事实，售后进度通过售后单和订单售后摘要展示。
- 商家后台以售后处理队列、待收货、退款跟踪为主。
- 管理员后台以客服工单、退款异常、风控风险、任务审计为主。
