# M3 Order State Machine

本文档定义 M3 购物车、结算、订单创建、模拟支付和库存占用的产品规则。M3 重点是把交易主链路做深；售后、退款、商家发货和客服工单的完整实现放到 M4，但 M3 的订单、支付、库存事件必须为后续售后与履约留出状态、审计和幂等基础。

## 1. 范围与原则

M3 覆盖：

- 用户购物车增删改查、选中、SKU 失效提示。
- 结算页重新校验商品、价格、库存、地址和运费。
- 订单创建、订单商品快照、价格快照、地址快照。
- 订单主状态机和子订单状态同步。
- 库存锁定、支付成功扣减、取消或超时释放。
- 模拟支付单、支付发起、支付成功/失败/超时回调。
- 重复支付回调、乱序回调、前端断网后的主动查单。
- 用户、商家、管理员在订单链路中的权限和可见状态。

M3 暂不覆盖：

- 真实第三方支付渠道接入。
- 完整退款、退货、客服介入和资金对账。
- 多包裹发货、自动收货和完整物流轨迹。

设计原则：

- 创建订单时锁定库存，未支付不扣减真实库存。
- 支付成功只允许从有效待支付订单进入已支付状态。
- 支付、取消、关闭、库存释放都必须幂等。
- 所有状态迁移必须写入状态事件；敏感操作必须写入审计日志。
- 用户端、商家端、管理员端看到的是同一订单事实，但字段和操作按角色脱敏与授权。

## 2. 参与角色

| 角色 | M3 可执行动作 | M3 禁止动作 |
|---|---|---|
| 普通用户 | 管理本人购物车、结算本人购物车、创建本人订单、发起本人模拟支付、取消本人待支付订单、查看本人订单 | 查看他人购物车或订单、修改订单价格、处理商家订单、直接修改支付状态 |
| 会员用户 | 普通用户能力，后续可扩展会员价和优惠 | 越权访问其他会员等级权益 |
| 企业用户 | 普通用户能力，后续可扩展采购审批 | 查看其他企业主体订单 |
| 商家店主 | 查看本店订单、待履约订单、订单商品和收货信息脱敏视图 | 查看跨店铺订单、触发支付、关闭用户订单 |
| 订单客服 | 查看本店订单、协助修改未发货订单备注或可配置字段 | 跨店铺处理、修改金额、直接改支付状态 |
| 仓储发货 | 查看本店已支付待发货订单，为 M4 发货预留操作入口 | 售后裁决、退款、财务数据访问 |
| 商家财务 | 查看本店支付摘要、结算相关只读信息 | 修改订单状态、修改商品和库存 |
| 平台客服 | 查看订单时间线和用户/商家基础信息，协助定位异常订单 | 绕过状态机直接退款或改价 |
| 风控审核 | 标记风险订单、关闭未支付风险订单、冻结待人工复核 | 商品运营配置、商家结算 |
| 财务管理员 | 查看支付单、模拟支付流水和异常支付记录 | 商品审核、客服裁决、直接发货 |
| 技术管理员 | 查看任务、日志、幂等记录和回调处理结果 | 直接处理业务资金或修改订单归属 |
| 只读审计 | 查看订单、支付、库存、审计事件 | 任何写操作 |

权限实现应沿用 `docs/product/rbac-matrix.md` 的四层模型：菜单权限、接口权限、数据范围权限、字段权限。

## 3. 核心对象

| 对象 | 说明 | 关键要求 |
|---|---|---|
| `cart` | 用户购物车容器 | 只归属当前用户；未登录用户可用本地购物车，登录后合并策略由前端和 API 契约确定 |
| `cart_item` | SKU、数量、选中状态 | 保存加入时价格用于提示，不作为下单价格事实 |
| `checkout_draft` | 结算草稿或结算预览 | 重新计算价格、库存、运费、地址可配送性；默认不锁库存 |
| `order` | 订单主单 | 保存用户、总金额、支付状态、关闭原因、地址快照、状态 |
| `order_item` | 订单商品行 | 保存 SKU、商品名、规格、图片、单价、数量、商家、商品快照 |
| `order_status_event` | 订单状态事件 | 记录前后状态、触发人、触发来源、原因、时间 |
| `inventory_reservation` | 库存锁定记录 | 用订单号和幂等键绑定；支付成功扣减，取消/超时释放 |
| `payment` | 模拟支付单 | 绑定订单、金额、渠道、状态、回调流水号和幂等键 |
| `audit_log` | 审计日志 | 记录敏感操作、权限拒绝、后台操作、风控关闭 |
| `notification` | 消息通知 | 用户、商家、后台待办状态变化通知 |

## 4. 购物车规则

购物车不是价格事实来源，只是用户的购买意向集合。

| 场景 | 规则 | 用户可见反馈 |
|---|---|---|
| 添加 SKU | SKU 必须已上架且有可售库存；数量不能小于 1 | 成功后显示当前数量和可售提示 |
| 修改数量 | 不能超过单次购买限制或当前可售库存策略 | 库存不足时提示最大可买数量 |
| 删除商品 | 只影响当前用户购物车 | 删除后不影响历史订单 |
| 勾选商品 | 结算只读取选中项 | 失效商品自动取消选中或阻止结算 |
| 商品下架 | 购物车保留商品行但标记失效 | 提示商品已下架，不可结算 |
| 价格变化 | 购物车展示旧价提示，但结算使用实时价 | 结算页显示价格变动明细 |
| 登录合并 | 本地购物车与服务端购物车合并时按 SKU 合并数量 | 超限或失效项需要明确提示 |

购物车接口必须校验本人数据范围。普通用户不能读取或修改其他用户购物车；商家和管理员不能代替用户编辑购物车，除非后续有明确的客服代客下单流程和审计规则。

## 5. 结算规则

结算页每次打开都要重新计算，不得信任购物车缓存。

结算校验顺序：

1. 校验登录态和当前用户。
2. 读取当前用户选中购物车项。
3. 校验 SKU 是否存在、已上架、商家和店铺状态是否允许售卖。
4. 校验购买数量、限购规则、库存可售数量。
5. 重新计算商品金额、运费、优惠和应付金额。
6. 校验收货地址完整性、可配送性和字段脱敏展示。
7. 返回结算预览和阻塞项。

结算结果分为：

| 结果 | 含义 | 下一步 |
|---|---|---|
| `checkout_ready` | 所有选中项可结算 | 用户可提交订单 |
| `needs_user_action` | 地址缺失、发票信息缺失、价格变化需要确认 | 用户补充或确认后重新结算 |
| `blocked` | 商品失效、库存不足、不可配送、权限异常 | 阻止下单，展示每个阻塞项 |

M3 默认结算预览不锁库存，只有创建订单时才在同一事务内创建库存锁定。若后续引入结算草稿锁库存，需要单独定义草稿 TTL、释放任务和幂等策略。

## 6. 订单创建

订单创建必须是事务性操作，不能出现订单已创建但库存未锁定、或库存已锁定但订单不存在的中间结果。

创建步骤：

1. 用户提交结算确认，请求携带 `idempotency_key`。
2. 服务端重新执行结算校验。
3. 按商家或履约单元拆分子订单；M3 可先使用单主单、多商品行结构，但字段要预留 `merchant_id` 和子单扩展。
4. 写入订单主单、订单商品快照、地址快照和价格快照。
5. 为每个 SKU 创建库存锁定记录。
6. 写入订单状态事件：`null -> pending_payment`。
7. 清理或取消勾选已下单购物车项。
8. 返回订单号、应付金额、支付截止时间和支付入口。

幂等规则：

- 相同用户、相同 `idempotency_key`、相同请求摘要重复提交时，返回第一次创建的订单。
- 相同 `idempotency_key` 但请求摘要不同，返回冲突错误。
- 创建失败必须整体回滚，不得残留库存锁定。
- 用户重复点击提交订单、网络重试、前端刷新都不能重复扣占库存。

## 7. 订单状态机

M3 订单主状态：

```text
pending_payment
  -> paid_pending_shipment
  -> shipped_awaiting_receipt
  -> completed

pending_payment
  -> closed

paid_pending_shipment
  -> closed
```

M3 重点实现 `pending_payment`、`paid_pending_shipment`、`closed`。`shipped_awaiting_receipt` 和 `completed` 作为 M4 履约与售后扩展状态预留。

| 当前状态 | 目标状态 | 触发方 | 条件 | 库存动作 | 审计/事件 |
|---|---|---|---|---|---|
| `null` | `pending_payment` | 用户 | 订单创建成功，库存锁定成功 | 锁定库存 | 状态事件、库存事件 |
| `pending_payment` | `paid_pending_shipment` | 模拟支付回调或支付查询补偿 | 支付单金额匹配、订单未关闭、支付未过期或在允许补偿窗口 | 扣减库存或确认锁定转扣减 | 状态事件、支付事件、通知商家 |
| `pending_payment` | `closed` | 用户 | 用户主动取消且未支付 | 释放库存 | 状态事件、库存事件 |
| `pending_payment` | `closed` | 系统任务 | 超过支付截止时间且未支付 | 释放库存 | 状态事件、库存事件、任务日志 |
| `pending_payment` | `closed` | 风控审核 | 风险命中且未支付 | 释放库存 | 审计日志、状态事件、通知用户 |
| `paid_pending_shipment` | `closed` | 系统或财务补偿 | M3 仅允许支付后异常补偿关闭；正常取消退款放到 M4 | 不释放已扣减库存，需走退款/补偿流程 | 审计日志、支付异常事件 |
| `paid_pending_shipment` | `shipped_awaiting_receipt` | 仓储发货 | M4 发货能力开启后，物流单校验通过 | 无 | 状态事件、通知用户 |
| `shipped_awaiting_receipt` | `completed` | 用户或系统任务 | 用户确认收货或自动收货 | 无 | 状态事件、通知商家 |

关闭原因必须区分：

- `customer_cancelled`：用户主动取消待支付订单。
- `payment_timeout`：系统支付超时关闭。
- `risk_control`：风控关闭。
- `payment_failed`：模拟支付失败后关闭，需保留失败码。
- `compensation_closed`：支付后异常补偿关闭，M3 仅记录能力边界。

禁止状态迁移：

- `closed` 不能重新打开。
- `paid_pending_shipment` 不能因重复取消请求释放库存。
- `pending_payment` 不能在金额不一致时支付成功。
- 已支付订单不能被用户普通取消接口直接关闭。
- 任何角色不能绕过状态机直接写订单状态。

## 8. 库存锁定、释放与扣减

库存事件必须和订单状态迁移保持一致。

| 触发场景 | 库存处理 | 幂等键 |
|---|---|---|
| 创建订单成功 | 从可售库存中锁定数量，写 `inventory_reservation` | `order_create:{order_id}:{sku_id}` |
| 创建订单失败 | 不保留库存锁定 | 创建订单 `idempotency_key` |
| 用户取消待支付订单 | 释放对应锁定库存 | `order_cancel:{order_id}` |
| 支付超时关闭 | 释放对应锁定库存 | `payment_timeout:{order_id}` |
| 风控关闭未支付订单 | 释放对应锁定库存 | `risk_close:{order_id}` |
| 支付成功 | 将锁定库存转为扣减，或标记锁定已消费 | `payment_success:{payment_id}` |
| 重复支付成功回调 | 不重复扣减 | 支付渠道流水号、回调事件 ID |
| 乱序失败回调晚于成功 | 不释放库存，不回退订单 | 支付渠道流水号、回调事件 ID |

并发要求：

- 同一 SKU 多用户同时下单时，成功锁定数量不能超过可售库存。
- 同一订单的取消任务、用户取消和支付回调并发时，只能有一个最终状态。
- 支付成功和支付超时任务竞争时，以数据库事务内的订单当前状态和支付事件时间为准；若支付已成功落库，超时任务不得关闭订单。
- 库存释放或扣减失败时，订单状态不得先行提交；如采用异步补偿，必须有明确的异常状态和任务告警。

## 9. 模拟支付

模拟支付需要保留真实支付适配层的形状，即使当前不接第三方渠道。

支付单状态：

```text
created
  -> paying
  -> succeeded

created
  -> failed

paying
  -> succeeded
paying
  -> failed
paying
  -> expired
```

支付发起规则：

- 只能为当前用户本人的 `pending_payment` 订单创建或复用支付单。
- 支付金额必须等于订单应付金额。
- 一个订单同一时间只能有一个有效支付单；重复发起返回现有支付单或创建新支付尝试需有明确版本。
- 支付单过期时间不能晚于订单支付截止时间。
- 前端支付页断网或刷新后，应通过订单详情或支付查询接口恢复状态。

模拟支付回调规则：

| 回调类型 | 处理规则 |
|---|---|
| 首次成功 | 支付单置为 `succeeded`，订单进入 `paid_pending_shipment`，库存转扣减 |
| 重复成功 | 返回成功处理结果，不重复改状态、不重复扣库存、不重复通知 |
| 首次失败 | 若订单仍在 `pending_payment`，支付单置为 `failed`；订单可继续允许重新支付或按策略关闭 |
| 重复失败 | 返回已处理结果，不重复通知 |
| 成功后失败 | 记录乱序回调事件，订单保持已支付，不释放库存 |
| 失败后成功 | 若订单仍待支付且金额匹配，可成功；若订单已关闭，进入异常支付记录并触发财务/技术待办 |
| 金额不一致 | 拒绝成功迁移，记录支付异常和审计 |
| 订单不存在 | 记录无主回调，触发财务/技术待办 |

支付回调必须使用至少一个稳定幂等标识，例如 `channel_transaction_id`、`callback_event_id` 或模拟渠道流水号。回调处理要记录原始请求摘要，但不能记录敏感凭证。

## 10. 支付超时关闭

订单创建时必须写入 `payment_deadline`。系统任务按截止时间扫描 `pending_payment` 订单。

超时关闭步骤：

1. 系统任务读取已过 `payment_deadline` 的 `pending_payment` 订单。
2. 在事务中锁定订单行或使用乐观版本。
3. 再次确认没有成功支付事件。
4. 订单状态迁移为 `closed`，关闭原因 `payment_timeout`。
5. 释放库存锁定。
6. 支付单置为 `expired`，若支付单已成功则不得关闭订单。
7. 写订单事件、库存事件、任务日志。
8. 通知用户订单已关闭。

超时任务必须可重复执行。重复扫描同一订单时，如果订单已关闭或已支付，应直接跳过并记录跳过原因。

## 11. 多端状态联动

| 状态变化 | 用户端 | 商家端 | 管理员端 |
|---|---|---|---|
| 订单创建待支付 | 展示待支付、支付倒计时、取消入口 | 默认不进入待发货队列，可在订单查询中只读查看 | 可在订单查询和风控队列查看 |
| 用户取消待支付 | 展示已关闭和关闭原因 | 不进入履约队列 | 可查看状态事件和库存释放 |
| 支付超时关闭 | 展示已关闭、提示重新购买 | 不进入履约队列 | 技术/客服可查看任务执行事件 |
| 支付成功 | 展示待发货、隐藏普通取消入口 | 进入本店待发货队列，通知商家 | 财务可查看支付单，客服可查看订单时间线 |
| 重复支付回调 | 不重复通知 | 不重复生成待办 | 财务/技术可查看幂等处理记录 |
| 风控关闭待支付 | 展示关闭原因的用户可见文案 | 不进入履约队列 | 风控和审计可见完整原因 |

字段权限：

- 用户只能看本人完整收货地址和本人手机号。
- 商家可按履约需要查看收货信息；列表页应脱敏，详情页按权限展示。
- 平台客服按工单或订单查询权限查看必要信息，访问敏感字段要写审计。
- 财务管理员可看金额、支付单和渠道流水，不默认查看完整收货地址。
- 只读审计可查看日志和报表，但不能触发状态变化。

| `POST /api/v1/payments/mock/callback` | 是或内部签名 | `payment:callback` | 模拟渠道或系统内部调用 |
| `GET /api/v1/merchant/orders` | 是 | `merchant:order:read` | 当前商家 `merchant_ids` |
| `GET /api/v1/merchant/orders/{order_id}` | 是 | `merchant:order:read` | 禁止跨商家 |
| `GET /api/v1/admin/orders` | 是 | `admin:order:read` | 按管理员角色和数据范围 |
| `POST /api/v1/admin/orders/{order_id}/risk-close` | 是 | `risk:order:close` | 风控角色，未支付订单，写审计 |
| `GET /api/v1/admin/payments` | 是 | `finance:payment:read` | 财务或授权管理员 |

## 13. 审计与事件

必须写订单状态事件：

- 创建订单。
- 用户取消。
- 支付成功。
- 支付失败。
- 支付超时关闭。
- 风控关闭。
- 支付回调重复或乱序处理。

必须写审计日志：

- 权限拒绝。
- 商家或管理员读取敏感字段。
- 风控关闭订单。
- 技术管理员查看或重放回调。
- 财务管理员查看异常支付记录。
- 支付金额不一致、订单不存在、订单已关闭后收到成功回调。

事件字段至少包含：

- `actor_type`：`user`、`merchant_user`、`admin_user`、`system`、`mock_payment_channel`。
- `actor_id`：系统任务可为空但要有任务名。
- `source`：Web、Android、merchant console、admin console、system job、callback。
- `object_type` 和 `object_id`。
- `before_status`、`after_status`。
- `reason_code` 和用户可见文案。
- `request_id`、`idempotency_key`、IP、User-Agent。
- `created_at`。

## 14. 错误与提示

| 场景 | 建议错误 | 用户可见提示 |
|---|---|---|
| 未登录结算 | `401` | 请登录后继续结算 |
| 越权访问订单 | `403` 或 `404` | 无权访问该订单 |
| SKU 下架 | `409` | 商品已下架，请重新选择 |
| 库存不足 | `409` | 库存不足，请调整数量 |
| 价格变化 | `409` | 商品价格已变化，请确认后再提交 |
| 重复下单同幂等键 | `200` 或 `201` 返回原订单 | 保持原订单结果 |
| 幂等键冲突 | `409` | 请求已变化，请刷新后重试 |
| 支付金额不一致 | `409` | 支付金额异常，请重新发起支付 |
| 订单已关闭后支付成功 | `202` 或异常受理 | 支付异常处理中，请联系客服 |
| 支付超时 | `409` | 订单已超时关闭，请重新下单 |

## 15. M4 预留点

M3 实现时要为 M4 留出以下扩展：

- 订单拆分为子订单、包裹和物流单。
- 已支付订单取消后进入退款/售后流程，而不是直接关闭。
- 商家发货、用户确认收货、自动收货。
- 售后单、退款单和客服工单关联订单状态事件。
- 优惠券、运费、组合商品和部分退款分摊。
- 财务复核和渠道对账。
